## D1. P0: своё ядро на Python (2026-07-26)

**Решение:** вариант B — своё ядро на Python. Neuroblox.jl не берём ни как основу,
ни как зависимость. Заимствуем паттерн «граф блоков → составная система» как
архитектурную идею, кода не берём.

**Обоснование:**
- Оба ключевых критерия (многотемповое интегрирование, эпизодическая динамика со
  сбросом) не покрыты Neuroblox и потребовали бы реализации с нуля в любом варианте.
- Связь как модуляция параметра (θ_i ← h(x_j)) — фундаментальное решение проекта.
  Neuroblox построен на суммировании состояний (jcn), перестроить нельзя.
- Проприетарная лицензия (EULA, source-available): код нельзя форкнуть, модифицировать
  или перераспределять. Стоп-фактор для академического проекта.
- Масштаб проекта (4 модуля, ~10–15 переменных состояния) не требует
  Julia-производительности. Batch-ось снимает вопрос: 1.45 часа вместо 130 часов
  на карту невозможного при голом numpy.

**Альтернативы:**
- Вариант A (Neuroblox как основа): отвергнут — K1, K2, K6 не покрыты, лицензия.
- Вариант C (Python + juliacall для солверов): отложен как запасной. Переход возможен
  без переделки архитектуры, если упрёмся в производительность.

**Полная оценка:** reports/neuroblox_evaluation.md

## D2. Batch-ось в контракте модуля (2026-07-26)

**Решение:** состояние модуля — массив формы (n_replicates, n_state), не вектор.
Batch-ось — требование фазы 1, наравне с многотемповостью и эпизодическим сбросом.

**Обоснование:** драйвер стоимости — число шагов × число прогонов, не число модулей.
Бюджет фазы 4 (карта невозможного): шаг DDM 1 мс, час модельного времени, 30 seed'ов,
сетка 20×20 = 43 млрд реплик-шагов. По одному прогону: 10.85 мкс/шаг → 130 часов.
Батч 12 000 реплик: 0.111 мкс/шаг → 1.45 часа. Ускорение ×97 на голом numpy.

**Что затрагивает:**
- drift(x, θ, u) и diffusion(x, θ): принимают и возвращают (n_replicates, n_state)
- Параметры: (n_replicates, n_params) для развёртки по ручкам
- Генератор шума: массив формы состояния
- Связи: поэлементно по батчу
- Эпизодический сброс: маска по репликам, не глобальное условие
- Наблюдаемые: по батчу

Дописать позже невозможно — batch-ось пронизывает все слои.

## D3. Численный слой: numpy с подготовкой миграции (2026-07-26)

**Решение:** numpy + свой батч. Не JAX+diffrax.

**Скорректированные веса критериев (поправки автора):**

| Критерий | numpy | JAX+diffrax | Вес |
|----------|-------|-------------|-----|
| C1. Отладка | + | − | высокий |
| C2. Установка | + | − | средний |
| C3. Stiff-солвер | − | + | условный: низкий при работающем мультитемпе, критический при отказе от него |
| C4. Якобиан | + | + | **низкий** (снижен): центральные конечные разности дают отн. ошибку 7.3e-11 по элементам и 4.5e-11 по собственным значениям (проверено на n=6, 200 точек, против аналитического якобиана), стоимость 0.23 мс. SymPy и дублирование не нужны. |
| C5. Batch-ось | ± | + | высокий |
| C6. Архитектура | + | − | высокий |

**Обоснование:** главный аргумент за JAX (C4, якобиан) снят — конечные разности
достаточны для гладкого drift. Оставшиеся преимущества JAX (C5 batch через vmap)
не перевешивают проблемы отладки (C1) и архитектурной совместимости (C6) на ранних
фазах, когда уравнения нестабильны и меняются часто.

**Дисциплина миграции (правило 20 CLAUDE.md):** drift и diffusion — чистые функции
(x, θ, u) → dx без мутации на месте и побочных эффектов, случайность извне.

**Порог пересмотра (численный, не «если упрёмся»).** Возвращаемся к JAX, если
выполнено любое из:
- полная развёртка карты невозможного превышает 4 часа настенного времени;
- размерность состояния композита превышает 50;
- понадобился implicit-солвер для СДУ.

**Альтернатива:** JAX + diffrax — отложена. Переход возможен без переделки архитектуры
благодаря правилу 20.

## D4. Среда в P2: раздельные задачи, композиция в P3 (2026-07-27)

**Решение:** вариант B — в P2 две раздельные реализации Environment:
1. Перцептивная задача (gradient coherence → drift rate) для DDM standalone.
2. Двурукий бандит с реверсиями для RL standalone.

**Условие:** контракт среды единый (next_trial, reward, reset). Составная среда
(перцептивный выбор внутри RL-задачи) в P3 получается композицией двух, а не
переписыванием с нуля. Если при входе в P3 выяснится, что интерфейс нужно ломать —
эскалация к автору, потому что тогда откладывание не экономит, а удваивает работу.

**Обоснование:**
- Standalone-валидация чище: каждый модуль проверяется на задаче из его литературы.
- Held-out DDM (квантильный профиль RT) и RL (Rutledge) не требуют составной среды.
- DDM требует градуированную трудность (бандит её не даёт); RL требует реверсирующиеся
  контингенции. Единая среда в P2 удвоила бы объём раньше, чем это нужно.
- Риск интерфейсного разрыва управляется условием стоп-эскалации.

**Альтернативы:**
- Вариант A (единая составная среда в P2): отложен до P3. Предпочтительнее, но
  удваивает объём среды в P2 без выигрыша для standalone-валидации.

## D5. Схема расщепления: Lie-Trotter snapshot (2026-07-27)

**Решение:** многотемповый интегратор использует Lie-Trotter (первого порядка):
медленный шаг читает быстрое состояние с конца предыдущего интервала (snapshot), затем
быстрые подшаги обновляют быстрые переменные.

**Обоснование:** для двусторонне связанной системы с зазором 10⁴ snapshot даёт ошибку
~0.57% на T=100 при dt_slow=1.0. Усреднение по интервалу дало бы ~0.006%.
Тест test_snapshot_splitting_error различает: bounds [0.1%, 1.0%] проходит только
snapshot.

Ошибка O(dt_slow) — допустима при малых dt_slow. Если потребуется точнее — переход на
Strang splitting (второй порядок) без ломки интерфейса.

## D6. Lie-Trotter достаточен, Strang не нужен (2026-07-27)

**Решение:** остаёмся на Lie-Trotter. Strang splitting не реализуем.

**Обоснование по числам:** измеренный порядок сходимости по dt_slow:

| dt_slow | ошибка | порядок (log₂) |
|---------|--------|----------------|
| 2.0 | 9.08e-3 | — |
| 1.0 | 4.48e-3 | 1.02 |
| 0.5 | 2.19e-3 | 1.03 |
| 0.25 | 1.05e-3 | 1.06 |
| 0.125 | 4.78e-4 | 1.13 |

Порядок чисто первый (1.02–1.13). При рабочих dt_slow=0.01–0.1 (arousal tier):
ошибка расщепления ≈ 0.006–0.06%, что много меньше ошибки от дискретизации Эйлера
и стохастического шума. Strang дал бы O(dt_slow²), но при 0.06% первого порядка
это улучшение до ~0.004% — не оправдывает удвоение сложности.

**Порог пересмотра:** если ошибка расщепления превысит 1% при рабочих dt_slow —
реализуем Strang.

## D7. Протоколы среды: Roitman & Shadlen 2002 + Behrens 2007 (2026-07-27)

**Решение:**
- PerceptualTask: протокол по Roitman & Shadlen (2002), DOI: 10.1523/JNEUROSCI.22-21-09475.2002.
  Когерентности: 0%, 3.2%, 6.4%, 12.8%, 25.6%, 51.2%.
  Сырые данные для квантилей RT: https://shadlenlab.columbia.edu/resources/RoitmanDataCode.html
- ReversalBandit: структура по Behrens et al. (2007), DOI: 10.1038/nn1954.
  Оригинал: reward probs 0.75/0.25 (stable), 0.80/0.20 (volatile), реверсии 30/40 проб.
  Наша параметризация: p_reward и volatility развязаны (D9), реверсии стохастические.
  Volatility — exposed-параметр; поведенческий тест различимости — в P2.4 (D9, E11).

**Обоснование:**
- Roitman & Shadlen — каноническая задача для DDM fitting с публично доступными сырыми
  данными. Квантили вычисляются напрямую (правило 1), не берутся из обзоров.
- Behrens — единственный широко воспроизведённый протокол с явной манипуляцией
  волатильностью. Volatility как exposed-параметр — прямое отображение из эксперимента.

Полная спецификация: specs/environment.md.

## D8. Обезьяньи данные вместо человеческих (2026-07-27)

**Решение:** для валидации DDM используются данные обезьян (Roitman & Shadlen 2002),
не людей. Стратегия: настройка на monkey N, отложенная проверка квантилей на monkey B.

**Обоснование:** monkey data — единственный публично доступный набор с trial-level RT
и coherence на каждой пробе, необходимыми для per-coherence квантильного сравнения.
Человеческие данные по random dot motion обычно опубликованы в виде агрегированных
сводок, непригодных для квантильного профилирования.

**Компромисс:** платформа предназначена для моделирования человеческих психических
состояний. DDM-параметры обезьян (drift sensitivity, non-decision time, threshold)
отличаются от человеческих. Принимаем: функциональная валидация (воспроизводит ли
модель паттерн RT × accuracy × coherence) переносима между видами; абсолютные
значения параметров — нет. При появлении подходящих человеческих данных — переход
без изменения кода, только замена roitman_rts.csv.

**Дополнительное преимущество:** два субъекта (monkey N, B) дают настоящую
межсубъектную проверку — строже, чем внутрисубъектный split.

## D9. Развязка p_reward и volatility в бандите (2026-07-27)

**Решение:** p_reward и volatility — две ортогональные ручки, в отличие от Behrens 2007,
где вероятность вознаграждения связана с фазой (0.75 stable, 0.80 volatile).

**Обоснование:** две независимые ручки необходимы для:
1. Parameter recovery: восстановимость каждого параметра тестируется при фиксации другого.
2. Песочница: пользователь варьирует трудность и нестабильность независимо.
3. Факторный план: в карте невозможного нужна полная сетка p_reward × volatility.

**Цена:** невозможно точно воспроизвести двухфазный протокол Behrens одним набором
параметров. Для этого нужен двухблочный сценарий (P3: последовательность конфигураций).

**Второе отклонение:** стохастические реверсии (Geom) вместо фиксированных 30/40 проб.
Делает момент реверсии непредсказуемым для агента, что ближе к реальным задачам
с нестационарной средой.

Полная спецификация: specs/environment.md.

## D10: Гейтирование цикла проб по is_wake (2026-07-27)

**Контекст:** при gain ≈ 0.02 (сон) DDM drift падает до ~2% от нормы. За 7 дней ~32%
модельного времени — сон. Без гейтирования DDM будет накапливать случайные ответы.

**Решение:** arousal выдаёт `is_wake` (Q_m > Q_thresh). Гейт останавливает **цикл проб**
(стимул → решение → вознаграждение → обновление), а не быстрый тир. Непрерывная динамика
всех модулей продолжается во сне.

**Что замирает / продолжается:**
- Arousal: шагает (управляет циклом).
- DDM: drift ≈ 0, не достигает порога → trial_done=False, нет сбросов.
- RL+Mood: mood эволюционирует (drift ≠ 0); V не обновляется (нет проб → нет δ).

**Альтернатива (отвергнута):** заморозить быстрый тир целиком. Проблема: настроение
обязано эволюционировать во сне (физиология). При четвёртом модуле (BAA) ошибка
станет явной.

**Следствие:** правило 19а добавлено в CLAUDE.md — анализ устойчивости гибридных
(кусочно-гладких) систем на переключениях, не только внутри режимов.

Полная спецификация: specs/arousal.md, раздел «Поведение во время сна».

## D11: Переменная clock и выход is_wake (2026-07-28)

**Расхождение:** спецификация v2.2 объявляет 3 переменные состояния (vv, vm, h) и
2 выхода (gain, Qm). Реализация содержит 4 переменные (+ clock) и 3 выхода (+ is_wake).

**clock:** контракт модуля не передаёт время в drift(x, θ, u). Циркадный привод
C(t) = c0 + cos(ω(t − α)) требует доступа к модельному времени. Стандартный приём
для неавтономных ОДУ: вводим переменную clock с drift = 1.0, diffusion = 0.
Не физическая переменная, не участвует в динамике и связях, не модулируется.
Альтернатива — расширить контракт ядра (добавить t в drift) — ломает P1 API.

**is_wake:** булев выход Q_m > Q_thresh. Добавлен для гейтирования цикла проб (D10).
Без него гейт невозможен: внешний потребитель должен знать режим (сон/бодрствование)
из выхода модуля, а не вычислять Q_m самостоятельно.

Оба решения разумны; ошибка — не объявить расхождение. Спецификация обновлена до v2.3.

## D12: Компромисс длительности сна и отклика на депривацию (2026-07-29)

**Следствие для песочницы:** v_vh — exploratory. При крутке v_vh пользователь должен
видеть обе зависимости: длительность сна и депривационный отклик. Это иллюстрирует,
что модель PR07 жёстко связывает два клинических явления через один параметр.

**Следствие для литературы:** в литературе по PR07/Saper flip-flop оба наблюдаемых
(нормальный сон и отклик на депривацию) калибруются одновременно, но по отдельности.
Развёртка показывает, что при строгих количественных критериях окно параметров узкое.

Окно при σ_h=0.01: v_vh ∈ **≈[0.30, 0.34] = ~9.5%** от диапазона [0.08, 0.50].
results/arousal_vh_sweep_stochastic.json.

v_vh ∈ **≈[0.325, 0.35] = ~6%** от диапазона [0.08, 0.50].

помечается на ручке.

## D14: Расширение контракта trial_done и reset_state (2026-07-30)

## D16: DDMExtended с eta откладывается (2026-07-30)

**Статус:** принято.

**Контекст:** каноническая DDM (без eta, sz, st) прошла P2.3: первые моменты
(accuracy, mean RT) и межсубъектная проверка (monkey B) — PASS. Форма
распределения RT опровергнута: квантили расходятся (Q90 +23–34% при низких

(diff 66–201 мс при coh≥0.032). Причина установлена: отсутствие межпробной

1. Каноническая DDM закрыта как есть. Не пересматривается.
2. DDMExtended с eta (и при необходимости sz, st) заводится как **отдельный
   модуль** со своей спецификацией, своими отложенными и своим recovery.

3. Ставится в очередь **после завершения P2, до входа в P3**.

- Связь arousal.gain → κ действует на accuracy и среднее RT, которые

- Четвёртый параметр (eta) с известно плохой восстановимостью (Ratcliff &

**Условие подъёма в приоритете:** если в P3 или P4 обнаружится зависимость
результата (устойчивость композита, карта невозможного, поведение в

## D17: Ревизия критерия отложенной #3 DDM при coh=0 (2026-07-30)

**Статус:** принято.

**Хронология.** Отложенная #3 сформулирована как «RT-распределения correct
и error совпадают» с проверкой через KS-тест. При N≈5000 на группу KS дал
p=0.005 при coh=0, что формально FAIL. Анализ показал: Cohen d=0.04

Вердикт: критерий заменён, результат — PASS по новому критерию (|d|<0.1),

## D20: Исправление формулы λ_crit (2026-07-31)

**Статус:** принято (обновлено в v1.3).

**Порядок операций в коде:**
```python
# trial_update, строка mood update:
x_new[mask, 2] = (gamma * (m + delta))[mask]   # m ← γ·(m + δ)
```
Сначала прибавляется δ (RPE), затем результат умножается на γ (затухание).
Порядок: **затухание после прибавления δ**.

**Собственное значение:** m_{n+1} = γ·(m_n + δ). Линеаризация:
∂m_{n+1}/∂m_n = γ·(1 + λ·r_mean). Критическое: γ·(1 + λ_crit·r_mean) = 1.

**Корректная формула:** λ_crit = (1−γ)/(γ·r_mean), где γ = exp(−1/τ_m).

**Формула v1.1 (отвергнута):** (1−γ)/r_mean. Соответствовала бы порядку
«затухание до прибавления δ» (m_{n+1} = γ·m + δ, eigenvalue = γ + λ·r_mean).
Порог v1.1 в **1/γ ≈ 1.59 раз ниже** корректного, т.е. прежний ограничитель
был **излишне строгим, не небезопасным**.

При baseline (γ=0.63, r_mean=0.60): v1.1 давала 0.61, корректная даёт
0.97, численная — 1.23. Формула консервативна на ~20% (безопасное
направление для ограничителя ручки).

**Обновление v1.3:** затухание m перенесено из drift в trial_update.
Формула больше не содержит Δt (τ_m в пробах, обновление пробовое).

**Численная верификация:** experiments/rl_mood_lambda_crit.py →
results/rl_mood_lambda_crit.json. 5 значений τ_m, тест устойчивости
PASS (below: 100% stable, above: 93% diverged).

**Решение:** связь gain→β действует только в standalone RL (softmax choice).
В композите DDM+RL softmax не используется: DDM заменяет его noise-driven
accumulation. β в DDM-контексте — мёртвый параметр.

**Обоснование:** в value-based DDM резкость выбора = drift/threshold,
не exp(β·ΔV). Gain модулирует κ (→ drift), и κ/a уже контролирует
exploitation/exploration в DDM. Связь gain→β в композите дублировала бы
gain→κ по каналу, который не используется.

**P4:** exploration через порог a (DDM threshold), не β.

## D26: gain→α — основная arousal→RL связь для composite (2026-08-01)

**Статус:** принято автором.

**Решение:** gain→α реализована наряду с gain→β. α модулирует скорость
обучения ценностей; в композите ценности через value_diff → drift_bias
влияют на DDM. Связь действует во всех конфигурациях.

**Обоснование:** норадренергическая модуляция пластичности. Высокий arousal
→ быстрее обучение → V быстрее адаптируется к correct_arm. Эффект
обнаружим через accuracy и learning speed в composite.

**Ограничения:** recovery r=0.77 при N≥1000 (fitted). При N=500 exploratory.
Ограничение обратной задачи, не связи: связь действует, но оценка α из
данных требует длинных последовательностей.

**param_min=0, param_max=1.** α > 1 → V overshoots target. При gain=0.79,
s=4: α_eff = 0.15·0.16 = 0.024 > 0. При gain=1.05, s=4: α_eff = 0.15·1.20
= 0.18 < 1.0.

## D27: Замыкание контура DDM↔RL через drift_bias (2026-08-01)

**Статус:** принято автором.

**Решение:** RL.value_diff → DDM.drift_bias. drift = κ·coh·dir + s·(V1−V0).
Стандартная value-based DDM: drift содержит перцептивный и ценностный
компоненты.

**Обоснование:** контур замыкается: V → drift_bias → choice → reward → V.
При coh=0 выбор определяется обученными ценностями. При coh>0 перцепция
и ценности аддитивны.

**drift_bias параметр:** index 3, default 0, range [-50, 50], INTERNAL.
Не exposed: модулируется связью, не крутится вручную.

**Решение:** при is_timeout=1 trial_update не обновляет V (пропускает

## D21: Затухание m в trial_update, не в drift (2026-07-31)

**Статус:** принято.

**Контекст:** γ = 0.63 калибровано на пробу (Rutledge 2014). Три варианта
размещения затухания:
1. И в drift, и в trial_update — двойной счёт, ошибка.
2. Только в drift (dm/dt = −m/τ_m) — длительность пробы влияет на
   затухание: после трудной пробы (RT ~1 с) m затухает сильнее, чем
   после лёгкой (RT ~0.3 с). Артефакт.
3. Только в trial_update (m ← γ·(m + δ)) — пробовое обновление,
   инвариантное к длительности пробы. Согласовано с калибровкой γ.

**Решение:** вариант 3. drift(m) = 0. Затухание — в trial_update.

**Следствия:**
- λ_crit не зависит от Δt (длительности пробы). Формула: (1−γ)/(γ·r_mean).
- Поведение m одинаково при любой длительности пробы (тест инвариантности).
- В композите (P3): m обновляется на каждом trial_done DDM, не на каждом
  шаге интегратора. Частота обновлений зависит от когерентности, затухание
  за обновление — нет.
- При варианте B: медленная компонента получит собственный drift в
  астрономическом времени, быстрая останется пробовой.

## D31. project_state в контракте SDEModule (2026-08-02)

**Решение:** SDEModule получает метод `project_state(x, theta) → x` (default: identity).
Вызывается в integrator._step_module после каждого шага EM.

**Назначение:** clipping (projection to boundary) для модулей с ограниченными переменными
(BAA: A≥0, 0≤S≤S_max, W∈[W_min, W_max]).

**Терминология:** clipping (x → b при x > b) ≠ reflecting (x → 2b − x при x > b).
Текущая реализация — clipping. BAA валидировался в досье с клиппингом; замена на
reflecting изменила бы поведение относительно досье.

**Обоснование:** чистые функции (правило 20), не мутирует состояние. Альтернатива —
clamp внутри drift — нарушает пуантуальность EM и даёт ошибочные якобианы.

**Предупреждение об артефактах:** в досье BAA веса проводили 73–98% времени на
границе, ΔW = 3.5 = ширина коробки — измерялись константы клиппинга, а не динамика.
Переменная, проводящая значительную долю времени на границе, не информативна для
карты невозможного: наблюдаемая определяется ограничением, а не drift.

**Обязательное правило:** доля времени на каждой границе (lower/upper) для каждой
переменной каждого модуля с project_state ≠ identity репортится всегда. Порог 10%:
при превышении — предупреждение, узел помечается как недостоверный для карты
невозможного.

**Обратная совместимость:** default = identity. Arousal, DDM, RL не затронуты.

2. Сила связей снижена до s_kappa=1, s_alpha=1, s_value=1.

## D36. P4: автономность arousal в карте связей (2026-08-03)

**Факт:** все связи в тройном композите однонаправленные от arousal:
- arousal.gain → DDM.kappa (параметрическая)
- arousal.gain → RL.alpha (параметрическая)
- RL.value_diff → DDM.drift_bias (замкнутый контур DDM↔RL)
- arousal.is_wake → trial gate (структурная)

Ни одна связь не имеет `target_module="arousal"`. Обратной связи нет.

**Следствие:** динамика arousal (цикл сна-бодрствования, gain, h, vm, vv)

не варьируют. Карта в координатах сил связей не может показать ничего

**Правило:** при добавлении ручек самого arousal (v_vh, σ_h и т.д.) в будущие
карты потребуется: (а) T ≥ 86400 (полный суточный цикл); (б) прогрев из
откалиброванного состояния; (в) арузальные наблюдаемые включаются явно.

## D37. P4: схема не огрубляется ради бюджета (2026-08-03)

**Контекст:** суточный прогон при dt_fast=0.001, B=225, n_rep=1 стоит 4.3 ч/карту
(порог D3 пограничный). Предложено огрубить шаг до dt_fast=0.01 (26 мин/карту).

**Проверки:**
1. Accuracy при рабочих когерентностях: dt=0.01 сдвигает accuracy вверх на
   0.007–0.012 абс. Сдвиг зависит от когерентности (больше при низких coh).
2. RT bias: постоянен по s_kappa (+3.0 ± 0.1%).
3. Accuracy bias по s_kappa: не проверен. В композите эффективная когерентность
   зависит от κ_eff, т.е. от s_kappa (оси карты). Проверка однородности accuracy

**Решение:** dt_fast=0.01 отклонён. Численная схема не огрубляется ради бюджета.

этой корреляции требует отдельного анализа, тогда как честный расчёт при dt=0.001
даёт результат без оговорок. Калибровка, recovery и отложенные наблюдаемые
выполнены при dt=0.001 — пересматривать их не нужно.

## D38. Гонка реверсий в next_trial (2026-08-04)

**Статус:** исправлено.

### Механизм

`Integrator._handle_trials()` при `trial_done` реплики i вызывает
`env.next_trial(rng)`. До исправления `next_trial()` обновлял внутреннее
состояние среды (correct_arm, счётчики проб, _current_direction) для ВСЕХ
B реплик, включая те, что ещё накапливают evidence в текущей пробе.

Две затронутые среды:
- **CompositeTask:** `correct_arm` переворачивался с вероятностью p_rev=volatility/20
  для всех B реплик. Стимул (direction) обновлялся только для done реплик
  (через `np.where(done, new_stim, stimulus)` в интеграторе), но correct_arm
  менялся для всех. Результат: когда реплика j завершала свою пробу,
  `reward()` сравнивал её выбор с correct_arm[j], который уже был перевёрнут
  чужими вызовами next_trial.
- **PerceptualTask:** `_current_direction` перезаписывался для всех B.
  Аналогичная проблема, но без реверсий (direction просто случайный).

### Условия проявления

Баг проявляется при **одновременном** выполнении трёх условий:
1. B > 1 (несколько реплик)
2. trial_done **асинхронно** по репликам (DDM: разные реплики достигают
   порога в разное время)
3. volatility > 0 (CompositeTask) или direction значим для reward (PerceptualTask)

При B=1 — нет чужих реплик. При синхронном trial_done (standalone RL, где
trial_done=True на каждом шаге для всех) — все обновляются одновременно.
При volatility=0 — correct_arm не меняется, direction и correct_arm
согласованы.

### Как обнаружен

Первый запуск карты невозможного при B=225, coh=0.128 показал accuracy 0.506
(ожидалось 0.91–0.96). 57 из 225 точек CHANCE, 159 INDISTINGUISHABLE.
Диагностика: при coh=0.128 DDM drift = 14.7 × 0.128 ≈ 1.89, accuracy
должна быть ~0.96. Вычисление P(реверсия за пробу) при B=225:
1−(1−0.015)^225 ≈ 0.97 → direction и correct_arm рассинхронизированы
практически на каждой пробе.

Аналогичный класс бага, что NaN-заполнение в recovery возбуждения (A5):
скрытое состояние, общее для реплик батча, обновляемое без маскирования.

### Исправление

`Environment.next_trial(rng, mask=None)`:
- mask: (B,) bool. None → все реплики (обратная совместимость).
- Счётчики: `+= mask.astype(int)` вместо `+= 1`.
- Реверсии: `reverse = mask & (rng.random(B) < p_rev)`.
- PerceptualTask: `_current_direction = np.where(mask, direction, old)`.

Интегратор: `env.next_trial(self.rng, mask=done)`.

CompositeTask.reward() дополнительно возвращает `chose_correct`:
`n_correct` считает правильные выборы, не вознаграждения (A14).

Затронутые файлы: `environment.py`, `composite_task.py`, `reversal_bandit.py`,
`perceptual_task.py`, `integrator.py`, `conftest.py`, `test_integrator.py`.

| 0.128 | 0.948 | −4.0% | +0.7% | −7.1% |
| 0.064 | 0.806 | −3.2% | +7.0% | −7.3% |
| 0.032 | 0.670 | −1.4% | +13.0% | −1.9% |

**Формулировка:** перенос выученных ценностей в решение замещает перцептивное
свидетельство ровно в той мере, в какой оно слабо. При сильном перцептивном
сигнале (coh=0.128) drift_bias = s·(V1−V0) мал относительно κ·coh·dir ≈ 1.89
и не меняет ни accuracy, ни RT. При слабом (coh=0.032) κ·coh·dir ≈ 0.47, и
drift_bias того же порядка качественно меняет поведение: accuracy +13% при
s_value=10.

Обратный эффект (s_kappa) слабеет с уменьшением когерентности: −4% при
coh=0.128 → −1.4% при coh=0.032. Причина: κ_eff снижает drift, но при малом
coh baseline drift уже мал, и дальнейшее снижение не порождает ошибок —
DDM работает на шуме, не на drift. Зато value-based bias замещает потерянный
перцептивный drift.

**Ни DDM, ни RL по отдельности этого не дают.** DDM standalone не обучается
ценностям. RL standalone не имеет перцептивного сигнала. Замещение — свойство
композита: value_diff → drift_bias работает как второй канал доказательства,
независимый от когерентности стимула.

**Немонотонность D29 воспроизведена** на всех трёх когерентностях: s_value=20
ухудшает accuracy. При coh=0.032 ухудшение слабее (−1.9% vs −7.1% при 0.128) —
при слабом перцептивном сигнале value bias дольше полезен.

**Следствие для P5 (песочница):**
1. Эффект coupling strengths зависит от coherence. Песочница должна позволять
   менять когерентность и наблюдать, как изменяется паттерн.
2. s_value и coherence — функциональные заменители: оба добавляют drift. При
   низкой когерентности RL «достраивает» перцептивный дефицит.
3. Диапазон полезности s_value шире при низких coh: при coh=0.032 даже s=20
   снижает accuracy всего на 1.9%. Красная зона s_value зависит от когерентности.

`results/p4_impossible_map_kappa_value_coh0.032.json`,
`results/p4_impossible_map_kappa_value.json` (coh=0.128).

## D40. BAA tonic_input как параметр, не ветвление в drift (2026-08-04)

**Статус:** принято. Откат предыдущей правки.

**Проблема.** BAA в композите получает u=zeros(B,5): stimulus CompositeTask
(coherence, direction) не совпадает с BAA input_names (I0..I4). Стимул
к BAA не адресован — у него в этой конфигурации нет внешнего источника входа.
Первая попытка: ветвление `if np.any(u != 0): use u else: use tonic_input`
внутри drift. Это скрытая ветка (правило 5), неотличимая от «связь выдаёт ноль»
и меняющая уравнение модуля.

**Решение.** tonic_input — параметр модуля (param[13], Exposure.INTERNAL).
Drift: `I = tonic + u[:, :nc]`. Тонический вход присутствует всегда; внешний
стимул добавляется сверху. При u=0 (нет стимула): I = tonic_input. При u>0:
I = tonic + stimulus. Нет ветвления, два случая различимы.

Физиологически: тонический вход = базальный уровень возбуждения от подкорковых
структур, модулируемый arousal через gain. Внешний стимул — задачно-специфичный
вход, который может отсутствовать (композит без перцептивной задачи для BAA).

**Тесты:** standalone тест fixed point — tonic_input=0 в theta, чистый внешний
вход. Composite тесты — tonic_input=0.5 (default), u=0.

**n_params:** 13 → 14.

## D42. BAA — пассивный слушатель (2026-08-04)

**Статус:** зафиксирован.

**Факт.** BAA в текущей конфигурации:
- Принимает arousal.gain через coupling (D33).
- Не влияет ни на один другой модуль — нет coupling с source_module="baa".
- Не получает адресованного стимула — stimulus CompositeTask (coherence,
  direction) не совпадает с BAA input_names (I0..I4). Используется
  tonic_input из theta (D40).
- Не участвует в цикле проб — на slow tier, trial_done = False (default).

**Следствие:** вращение ручек BAA (gain, beta, gamma, sigma_base, tonic_input)
не меняет ни одной поведенческой наблюдаемой из карты невозможного
(accuracy, mean_rt, win_stay_rate). Нет обратного пути BAA → DDM/RL/arousal.

**Требование к песочнице (P5).** Пользователь должен видеть это явно — что
BAA отключён от решательного контура — а не обнаруживать опытным путём,
покрутив ручки без эффекта. Визуальная пометка: «наблюдает, не управляет».

**Варианты развития (отложены, не выбраны):**

1. **Собственные наблюдаемые BAA.** total_activation, energy, attention_entropy
   уже вычисляются (outputs). Вывести их в песочницу как отдельную панель.
   Показывают, как arousal модулирует внимание, без обратной связи.
   Стоимость: минимальная (код есть).

2. **Адресованный стимул + включение в цикл проб.** BAA получает перцептивный
   вход (coherence → I каналы). BAA определяет «куда смотрит» → модулирует
   coherence, видимую DDM. Замкнутый контур: attention → perception → decision.
   Стоимость: значительная (новая связь, пересмотр trial loop, устойчивость).

3. **Обратная связь BAA → DDM как модуля внимания.** BAA.attention_entropy
   или total_activation → DDM.kappa. Высокая энтропия = расфокусированное
   внимание = низкий κ. Параллельный канал к gain→κ.
   Стоимость: средняя (coupling + устойчивость, но без trial loop).

Выбор — эскалация к автору (правило 8). Каждый вариант меняет научное
содержание: что моделирует BAA в платформе.

**Статус:** эскалация, принято.

**Zou et al. (2022):** файлы на OSF (https://osf.io/jde6m/) пусты —
data_both_blocks_only.mat и readme.txt по 0 bytes. Подтверждено прямой
проверкой curl и urllib (2026-08-04). Черновик запроса авторам подготовлен.

**Замена:** Eckstein, Master, Dahl, Wilbrecht & Collins (2022),
Dev Cogn Neurosci 55:101106. OSF: https://osf.io/7wuh4/.
Первоисточник протокола, на который ссылается Zou. 291 участник 8–30 лет.
Данные доступны, скачаны, формат проверен.

**Обоснование замены:** Zou ссылается на Eckstein как на источник протокола.
Eckstein — больше выборка (291 vs 70), данные доступны, тот же протокол.

**Отличия протокола Eckstein от ReversalBandit:**
- p_reward индивидуальный (~0.64–0.99), у нас фиксированный (0.75).
  Среда адаптируется под каждого участника.
- p_switch индивидуальный (~0.03–0.26). Отображается на volatility.
- 131 проба на участника. **Ниже порога 500 для β recovery.**

**Следствие 120 проб < 500:** β не оценивается из данных (r=0.90 при
N=500, неизвестен при N=120). Сравнение — **поведенческое**, как для arousal:
фиксируем всё на калиброванном, сравниваем WS, LS, ACC.

Авторские оценки (α=0.76, β=3.53) **несопоставимы** с нашими (α=0.15,
β=2.50): разные протоколы, разные оценщики, разные выборки. Eckstein et al.
(eLife 2022) показали, что параметры RL не переносятся между задачами.
Записывается как несопоставимость, не как расхождение.

**Протокол Eckstein несовместим с ReversalBandit:**
- Реверсия по критерию (7–15 rewards), не по вероятности.
- p_incorrect = 0 (у нас 0.25).
- Переключение только после reward.
Адаптация среды — за пределами P6. Сравнение при нашем протоколе.
Несовместимость — ограничение сравнения.

**Ограничения:** возраст 8–30, включая детей. Модуль калиброван на
взрослых (Rutledge 2014). Сравнение — со взрослой подвыборкой (18+).

## D46. Баг знаков в MLE DDM density (2026-08-05)

**Статус:** исправлено.

**Механизм.** В плотности Навальника—Фусса для DDM два слагаемых:
- Upper boundary (correct): exp(+v·a/2 − v²t/2) × f̃(τ)
- Lower boundary (error): exp(−v·a/2 − v²t/2) × f̃(τ)

В реализации знаки были перепутаны: upper получил exp(−v·a/2),
lower — exp(+v·a/2). В результате правильный ответ становился
менее вероятным с ростом drift, а ошибка — более. NLL росла с
kappa: optimizer гнал κ к минимуму вместо истинного значения.

**Как обнаружен.** Синтетическая проверка восстановимости (recovery)
перед прогоном по реальным данным. При N=500 пробах, 25 точках:
κ r=−0.000, a r=−0.293, Ter r=0.929. κ и a не восстанавливались.
NLL при истинном κ=15 была выше, чем при κ=5 — монотонное
возрастание вместо минимума. Проверка NLL landscape по одному
параметру показала перевёрнутую зависимость.

**Как проявился бы без обнаружения.** На реальных данных оценщик
выдал бы правдоподобные числа: κ → нижняя граница, a → заниженное,
Ter → смещённое. Оценки выглядели бы осмысленно (κ≈1, a≈0.5) и
прошли бы проверку диапазона. Сравнение модели с данными показало
бы систематическое расхождение, которое было бы приписано модели,
а не ошибке реализации. Причина была бы неотличима от «модель не
соответствует данным» без синтетической проверки.

**Вывод для методологии.** Синтетическая проверка восстановимости —
не формальность, а обязательный шаг: ловит ошибки реализации, а не
только свойства модели. В статье: recovery перед сравнением.

**После исправления:** κ r=0.889, a r=0.995, Ter r=0.990 (N=500, 50 точек).
Все три fitted. Кросс-корреляции < 0.10.

## D47. Восстановимость и предсказательная способность — разные свойства (2026-08-05)

**Статус:** зафиксирован. Результат P6.

**Наблюдение.** Arousal — единственный модуль, где ни один параметр не
восстановим (все exploratory, r = 0.05–0.41). Именно он дал самое чистое
согласие с реальными данными:
- Длительность сна: модель 8.32h, данные 8.31h (алг. 1) / 7.95h (алг. 2).
  Модель в 95% CI обоих алгоритмов.
- Момент засыпания: разница 26 мин = 0.23 кругового SD.
- Ни один параметр не оценивался из данных.

DDM, где все три параметра fitted (r > 0.89), дал неопределённый результат
на многоусловных наборах (MAE/threshold = 0.90) и положительный на
одноусловных и coherence-наборах.

**Вывод.** Восстановимость параметров и предсказательная способность модели —
разные свойства, которые в литературе часто смешивают. Модель может верно
предсказывать групповые характеристики (длительность сна, момент засыпания),
не позволяя оценить параметры отдельного человека. Обратное тоже верно:
восстановимость параметров (DDM κ, a, Ter) не гарантирует точного
предсказания наблюдаемых на произвольных данных.

**Причина разрыва у arousal:** модель Phillips-Robinson — двухпроцессная
(гомеостат + циркадный). При фиксированных параметрах она предсказывает
длительность и фазу сна из физиологической структуры, а не из подгонки.
Параметры невосстановимы, потому что flip-flop динамика порождает высокий
джиттер переключений (A5: SNR 0.9–3.8), а не потому что модель неверна.

**Дополнение из P6 данных.** Внутрииндивидуальный SD длительности сна
(2.50h) вчетверо превышает межиндивидуальный (0.66h): человек от ночи
к ночи меняется сильнее, чем люди между собой по средним. Индивидуальная
подгонка по нескольким ночам была бы малоосмысленна даже при восстановимых
параметрах — шум внутри человека доминирует над сигналом между людьми.

**Для статьи.** Правило 18 (классификация восстановимости) защищает от
неоправданной подгонки, но не предсказывает, какой модуль окажется ближе
к данным. Платформа разводит два вопроса: «можно ли оценить параметр из
данных?» и «верно ли модель предсказывает?». Ответы независимы.

## D49. Arousal duration comparison withdrawn (2026-08-06)

**Статус:** зафиксирован.

**Решение.** Сравнение по средней длительности сна снято. Три причины:
1. Утрата кода разметки (D48).
2. Недостаточная детализация предрегистрации: два противоречащих значения

   перекалибровки: все эпоховые алгоритмы в pyActigraphy (Cole-Kripke, Sadeh,

**Что остаётся.** Момент засыпания (не калибровался на эти данные — настоящее
предсказание), вариабельность момента (структурный разрыв), разложение
дисперсии (свойство данных). Все три устойчивы к выбору алгоритма разметки
(три варианта, robustness table в results/p6_arousal_comparison.json).

| Вариант | Onset (circ mean) | Onset within-SD | Within-SD dur | Between-SD dur |
|---------|------------------:|----------------:|--------------:|---------------:|
| p15 nonzero | 23.9h | 103 min | 2.18h | 1.01h |
| fixed 50 | 23.65h | 103 min | 2.18h | 0.98h |

## D50. DDM comparison: нормализация difficulty и классификация условий (2026-08-06)

**Статус:** зафиксирован. Дополнение к предрегистрации.

**1. Нормализация difficulty.** Сырые значения без сдвига.
Обоснование из формулы: v = kappa * difficulty инвариантно к умножению
(kappa поглощает множитель) и не инвариантно к сдвигу. Аффинная
нормализация [0,1] ставит нижний уровень на difficulty=0, давая
predicted accuracy = 0.5 по определению — что ошибочно.
Проверено на Desender_2022_Exp1: MAE raw = 0.056, MAE [0,1] = 0.112.
Предрегистрация не содержала указаний по нормализации.

**2. Классификация условий.** Критерий: колонка входит как difficulty,
если кодирует физическую трудность стимула (coherence, contrast,
SOA, noise level, dot difference). Колонки, кодирующие задачную
манипуляцию (speed/accuracy instruction, TMS site, block order),
игнорируются. 18 наборов пересмотрены по этому критерию.
Предрегистрация не определяла, какие колонки считать difficulty.

**3. Порог участников.** 50 проб на участника (MLE stable at N>=30).
Спецификация «200 проб» — порог на набор данных при отборе,
не на участника при анализе. При пороге 200: Bang_2019_Exp2
теряет 159 из 201 участников (медиана проб = 195).

**4. Масштабная классификация.** Спецификация не определяла
группировку наборов по типу шкалы (coherence/contrast/difficulty/ordinal).
Этот пробел аналогичен отсутствию указания прибора в актиграфии.
Восстановленный скрипт использует hardcoded список coherence-наборов.

## D52a. Баг is_multi=False в p6_ddm_comparison.py (2026-08-14)

(заглавная). Скрипт был восстановлен по спецификации (D48); оригинальный
скрипт утерян, поэтому неизвестно, был ли баг в оригинале.
