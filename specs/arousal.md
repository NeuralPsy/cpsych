Версия: 2.3. Дата: 2026-07-28. Статус: реализована, standalone validation в работе.

## Первоисточник

Phillips AJK, Robinson PA (2007). A quantitative model of sleep-wake dynamics
based on the physiology of the brainstem ascending arousal system. *J Biol Rhythms*
22(2):167-179. DOI: [10.1177/0748730406297512](https://doi.org/10.1177/0748730406297512)

Расширение (депривация): Phillips AJK, Robinson PA (2008). *J Theor Biol*
255(4):413-423. DOI: [10.1016/j.jtbi.2008.08.022](https://doi.org/10.1016/j.jtbi.2008.08.022)

Полная верификация уравнений и параметров: specs/arousal_sources.md

## Модель

Двухпроцессная flip-flop модель сна-бодрствования. Полная система из PR07 с тремя
переменными состояния. Алгебраическая редукция V_v (Skeldon et al. 2014, PLOS ONE,
DOI: 10.1371/journal.pone.0103877) **отвергнута**: при τ_v = τ_m = 10 с нет разделения
масштабов, адиабатическое исключение V_v неправомерно, бистабильность уничтожается
(reports/alternatives.md, A1). Полная система из 3 ОДУ воспроизводит устойчивый цикл
(results/arousal_demo.json).

Набор параметров: **PR08 с корректировкой v_vh** (v_vc=-3.2, chi=11 ч, alpha=16 ч
из PR08; v_vh=0.25 вместо 0.19, см. A2).

### Переменные состояния

| Переменная | Имя | Temporality | Initial | Единицы | Смысл |
|-----------|-----|-------------|---------|---------|-------|
| V_v | vv | CONTINUOUS | 0.0 | mV | Средний потенциал VLPO (промотор сна) |
| V_m | vm | CONTINUOUS | 0.0 | mV | Средний потенциал MA (промотор бодрствования) |
| H | h | CONTINUOUS | 15.0 | nM | Гомеостатическое давление сна (аденозин) |
| clock | clock | CONTINUOUS | 0.0 | s | Модельное время (D11: для C(t), не физическая переменная) |

### Уравнения

```
dV_v/dt = [v_vm * Q(V_m) + D(t) - V_v] / tau_v
dV_m/dt = [A + v_mv * Q(V_v) - V_m] / tau_m
dH/dt   = [mu * Q(V_m) - H] / chi
```

Алгебраические:
```
D(t) = v_vc * C(t) + v_vh * H
C(t) = c0 + cos(omega * (t - alpha))
Q(V) = Q_max / (1 + exp(-(V - theta) / sigma_q))
A = v_ma * Q(V_a0) ≈ 1.0 mV    (V_a0 = 1.0, без ОДУ)
```

Все уравнения — verified from deposited implementations of PR07 (specs/arousal_sources.md).

### Рабочий режим сигмоиды

Система работает на **левом хвосте** Q(V): theta=10 mV, но V_m ∈ [-14, +1] mV.
Следствие: Q(V_m) ∈ [0.03, 4.6] из теоретических [0, 100] s^{-1}. Это штатный
режим PR07, не ошибка — бистабильность возникает за счёт взаимной ингибиции при малых
Q, а не за счёт насыщения.

### Добавление шума (не в оригинале PR07)

Оригинальная модель детерминированная. Шум добавляем для СДУ-фреймворка:

```
diffusion(x, theta) → [sigma_vv, sigma_vm, sigma_h]
```

- sigma_vv: аддитивный шум на V_v. Существенно слабее sigma_vm.
- sigma_vm: аддитивный шум на V_m (флуктуации возбуждения). Калибруется по
  вариабельности момента засыпания/пробуждения (~15-30 мин SD между ночами;
  Klerman & Dijk 2005).
- sigma_h: аддитивный шум на H. Существенно слабее sigma_vm (H интегрирует часами).

**Устойчивость к шуму.** Стационарная дисперсия V_m от шума в OU-приближении:
Var ≈ sigma_vm² · tau_m / 2. При sigma_vm=0.5: std ≈ 1.1 mV, это 37% от sigma_q=3 mV.
Бистабильная система чувствительна к такому шуму — возможны паразитные переходы,
не объяснимые гомеостатом и циркадным ритмом. Тест: отложенная наблюдаемая #4.

Шум — конструктивное решение (не из PR07). Записан в alternatives.md (A3).

### Характерные масштабы

| Масштаб | Переменные | Значение |
|---------|-----------|----------|
| Нейрональный | V_v, V_m | tau_v = tau_m = 10 s |
| Гомеостатический | H | chi = 39600 s (~11 h) |
| Циркадный | C(t) | T = 86400 s (24 h, внешний) |

Жёсткость: tau_m / chi ~ 4000. Standalone: один тир с dt ~ 1s (разрешает V_v/V_m,
H медленно). В композите (P3): arousal в медленном тире.

### Разметка бодрствования

Порог состояния: **Q_thresh = 1.0 s^{-1}**. Бодрствование: Q(V_m) > Q_thresh.
Выбор: геометрическое среднее типичных Q_m сна (~0.1) и бодрствования (~4.5).

Зоны перехода: первые и последние **T_trim = 1800 с (30 мин)** каждого периода
бодрствования исключаются при вычислении gain statistics.

**Процедура разметки:**
1. Непрерывные интервалы Q_m > Q_thresh → периоды бодрствования.
2. Из каждого периода обрезать T_trim с начала и T_trim с конца → trimmed wake.
3. Если trimmed wake < 1 ч — период слишком короткий, исключить.
4. Пропуск первых суток (трансиент от начальных условий).

**Влияние обрезки на gain range (baseline):**
- С обрезкой ±30 мин: Q_m ∈ [3.40, 4.57], gain ∈ [0.79, 1.05]
- Без обрезки (включая переходы): Q_m ∈ [1.04, 4.57], gain ∈ [0.24, 1.05]

Все gain targets и swing привязаны к trimmed wake.

### Outputs

```python
# Калибровочная константа загружается из results/arousal_calibration.json
Q_M_WAKE_MEAN_BASELINE = load_calibration()  # 4.3318 s^{-1} при текущем baseline

def outputs(x, theta) -> dict:
    vv, vm, h = x[:, 0], x[:, 1], x[:, 2]
    Q_m = Q_max / (1 + exp(-(vm - theta_sig) / sigma_q))
    gain = Q_m / Q_M_WAKE_MEAN_BASELINE
    is_wake = Q_m > Q_THRESH  # 1.0 s^{-1}
    return {"gain": gain, "Qm": Q_m, "is_wake": is_wake}
```

- `gain`: Q(V_m) / Q_M_WAKE_MEAN_BASELINE — безразмерная модуляция относительно
  **фиксированной базовой линии**. Константа загружается из
  results/arousal_calibration.json (процедура вывода — раздел «Калибровочная
  константа»). Не пересчитывается при изменении ручек.

  Смысл: gain выражает **глобальный уровень возбуждения**, а не только внутрисуточную
  вариацию. При baseline среднее gain во время бодрствования = 1.000. При других
  параметрах среднее смещается:
  - v_vm=-0.50: g_mean=0.67 (ослабленная ингибиция → низкий arousal)
  - v_vc=-10.0: g_mean=1.07 (сильный циркадный привод → повышенный arousal)
  - A=1.50 (internal): g_mean=1.21

  Это психиатрическое содержание модуля: параметры не просто меняют форму цикла,
  а сдвигают уровень возбуждения.

  Диапазон:
  - gain ≥ 0 всегда (Q_m ≥ 0, константа > 0)
  - При бодрствовании gain ≈ 1.0 ± модуляция от параметров
  - gain > 1 — штатно (утренний пик, повышенный arousal)
  - Сон: gain ≈ 0.01–0.03

- `is_wake`: Q(V_m) > Q_thresh — булев сигнал состояния. Используется для
  гейтирования быстрого тира в композите (см. «Поведение во время сна»).

- `Qm`: абсолютная частота MA (s^{-1}). Диагностический выход, не для coupling.

### Калибровочная константа (Q_M_WAKE_MEAN_BASELINE)

Однократное вычисление при baseline параметрах:

1. Детерминированная симуляция при baseline θ (без шума, B=1).
2. Интегрирование посуточно. После каждых суток: разметка бодрствования
   (Q_thresh=1.0, T_trim=1800 с), вычисление ⟨Q_m⟩_wake за текущие сутки.
3. Критерий оседания: |⟨Q_m⟩_day_n − ⟨Q_m⟩_day_(n-1)| < 0.0001 s^{-1}.
   Использовать день n. Пропуск первых суток безусловный (трансиент).
4. При текущем baseline: день 2 удовлетворяет критерию (отстоит от асимптоты
   на 0.0001). Результат: **4.3318 s^{-1}**.

Процедура не привязана к фиксированной длительности 48 ч. При изменении baseline
(например, v_vh после recovery) время оседания может измениться — критерий
гарантирует корректность автоматически.

**Хранение и загрузка (правило 1):**

- Калибровочный скрипт `experiments/arousal_calibration.py` выполняет процедуру выше
  и записывает `results/arousal_calibration.json`:
  ```json
  {
    "Q_M_WAKE_MEAN_BASELINE": 4.332,
    "settled_day": 2,
    "settling_delta": 0.0001,
    "baseline_params": { ... },
    "procedure": "day-by-day until |delta| < 0.0001, Q_thresh=1.0, T_trim=1800"
  }
  ```
- Модуль при инициализации загружает константу из этого файла.
  Константа **не** хардкодится в коде модуля.
- Тест `test_arousal_calibration`: пересчитывает константу с нуля по документированной
  процедуре и сверяет с сохранённой в JSON. Допуск: |пересчитанная - сохранённая| < 0.001.
  Если baseline параметры изменились, а калибровка не пересчитана — тест падает.

Стоимость: 2–3 суток модельного времени × 86400 шагов × 3 переменных ≈ 0.5–0.8e6
float ops. Одноразово.

При изменении baseline параметров (например, корректировка v_vh в будущем) —
скрипт перезапускается, JSON обновляется, тест подтверждает.
При изменении **ручек** пользователем — **не** пересчитывается: это фиксированная
точка отсчёта.

### Temporality

CONTINUOUS — нет эпизодических сбросов. Arousal не участвует в trial loop.
`trial_done` → always False. `trial_update` → no-op.

### Поведение во время сна и следствие для композита

При gain ≈ 0.02 скорость дрейфа DDM падает до ~2% от нормы. Накопитель практически
не достигает порога, пробы не завершаются. За 7-дневную симуляцию ~32% модельного
времени — сон.

**Решение: гейтирование цикла проб по сигналу is_wake.**

Arousal выдаёт `is_wake` (Q_m > Q_thresh). В композите (P3) гейт останавливает
**цикл проб** (стимул → решение → вознаграждение → обновление), а не быстрый тир
целиком. Непрерывная динамика всех модулей продолжается во сне.

- **is_wake = True:** цикл проб работает нормально. Среда выдаёт стимулы,
  DDM накапливает свидетельство, при пересечении порога — вознаграждение,
  trial_update для всех модулей, reset эпизодических переменных, новая проба.
- **is_wake = False:** цикл проб заморожен. Среда не выдаёт новых стимулов.
  Непрерывная динамика (drift + diffusion) всех модулей **продолжает шагать**.

**Что замирает и что продолжается по модулям:**

| Модуль | Непрерывная динамика (drift) | trial_update | Во сне |
|--------|------------------------------|-------------|--------|
| Arousal | V_v, V_m, H эволюционируют | no-op | шагает (управляет циклом) |
| DDM | накопитель дрейфует (drift ≈ 0 при gain ≈ 0.02) | reset при решении | дрейф ~0, не достигает порога, не сбрасывается |
| RL+Mood | mood m эволюционирует (drift ≠ 0) | V += α·δ при решении | mood шагает; V не обновляется (нет проб → нет δ) |

DDM во сне: drift ≈ 0, накопитель практически неподвижен, порог не достигается,
trial_done = False, цикл проб не срабатывает. Это следствие gain ≈ 0.02, а не
внешнего запрета — модуль сам по себе корректен, гейт лишь гарантирует, что
пренебрежимый drift не породит случайных ответов за 8 часов шума.

**Обоснование выбора гейтирования цикла проб (не тира):**
- Экологическая валидность: испытуемые не выполняют задачи во сне.
- Физиологическая валидность: настроение продолжает эволюционировать во сне.
  RL-ценности не обновляются не потому, что тир заморожен, а потому что нет
  вознаграждений — это правильная причина.
- Нет артефактов: таймауты при gain≈0 не несут поведенческой информации.
- При добавлении четвёртого модуля (BAA) с непрерывной динамикой вне trial loop —
  архитектура не ломается.

**Следствия для архитектуры (P3):**
- Интегратор (core/integrator.py) получает опциональный gate signal. Gate
  контролирует вызов `trial_done` / `trial_update` / `env.next_trial`, а не
  шаги интегрирования. Все тиры продолжают шагать во всех режимах.
- Контракт coupling: связь arousal→DDM (gain модулирует drift rate) дополняется
  gate-связью (is_wake гейтирует цикл проб). Gate — структурная связь,
  проектируется отдельно от Coupling dataclass.
- **Устойчивость гибридной системы (правило 19а):** дискретный гейт делает
  композит кусочно-гладким. Анализ устойчивости — по каждому режиму отдельно
  плюс проверка переключений (см. CLAUDE.md, правило 19).
- Standalone (P2): гейтирование не действует, arousal тестируется без DDM.

## Границы области cycling

Система циклит (flip-flop переключения) только при определённых комбинациях параметров.
За пределами — постоянный сон или постоянное бодрствование. Границы найдены бинарным
поиском (порог: ≥10 переходов за 7 дней при фиксации остальных на baseline).

| Параметр | Граница cycling | Направление | Объявленный Low | Объявленный High |
|----------|----------------|-------------|-----------------|------------------|
| v_vm | -2.75 | cycles for v_vm > -2.75 | -2.70 | -0.50 |
| v_mv | -0.83 | cycles for v_mv < -0.83 | -5.00 | -0.90 |
| v_vc | нет границы | весь диапазон циклит | -10.0 | -1.0 |
| v_vh | 0.076 | cycles for v_vh > 0.076 | 0.08 | 0.50 |

**Запас:** объявленный диапазон отступает от границы на ~2–8% в сторону устойчивого
cycling. За пределами объявленного диапазона модуль не гарантирует осмысленный выход.

Это первый фрагмент **карты невозможного**: области параметров, где модель
отказывается производить нормальный сон-бодрствование.

**Интерпретация:**
- v_vm < -2.75: слишком сильная ингибиция MA→VLPO → VLPO подавлен, постоянное
  бодрствование (или постоянный сон при сильном гомеостате).
- v_mv > -0.83: слишком слабая ингибиция VLPO→MA → MA не может быть подавлен,
  flip-flop не переключается.
- v_vh < 0.076: слишком слабая чувствительность к аденозину → гомеостатическое
  давление не может переключить систему.

## Цели настройки

Настройка по детерминированному временному профилю при baseline параметрах:

1. **Продолжительность сна:** 7-9 ч (Q_m < Q_thresh).
2. **Момент засыпания:** ~23:00 ± 1 ч.
3. **Момент пробуждения:** ~07:00 ± 1 ч.
4. **Бистабильность:** ≥14 переходов за 7 дней. Линеаризация в каждом устойчивом
   состоянии даёт отрицательные Re(λ).
5. **Gain dynamic range (trimmed wake):** gain снижается в течение бодрствования
   от утреннего максимума к вечернему минимуму. Swing:
   (g_max - g_min) / g_max ≥ 15%, где g_max и g_min берутся по trimmed wake
   (процедура разметки выше). Отражает профиль бдительности: утренний пик,
   вечерний спад перед засыпанием.
6. **H монотонность:** H растёт во время бодрствования, падает во время сна.
   H(засыпание) > H(пробуждение).

Критерий успеха: все 6 целей выполнены при baseline параметрах (подтверждено
верификационным прогоном).

## Parameter recovery

### Процедура

Симуляция: **7 дней** (604800 шагов при dt=1s). ~14 переходов — достаточно.

Сетка: 5 значений на параметр, 20 реплик на точку.

**Наблюдаемые** (на реплику, из 7-дневной симуляции):

Моменты переходов (14):
- sleep_onset_1..7
- sleep_offset_1..7

Длительности (14):
- sleep_duration_1..7
- wake_duration_1..7

Gain-чувствительные (7):
- gain_swing_d = (Q_m_wake_max - Q_m_wake_min) / Q_m_wake_max, d=1..7

Итого: 35 наблюдаемых на реплику.

Метод: grid search + MLE на расстоянии между предсказанными и наблюдёнными.

### Вычислительная стоимость

3 кандидата (v_vh, v_vc, v_mv): 5³ = 125 точек × 20 реплик = 2500 прогонов.
С batch-осью B=2500: один вызов интегратора.
604800 шагов × B=2500 × 3 переменных ≈ 4.5e9 float ops.
Оценка: ~3 мин CPU (numpy vectorized).

**Онлайн-детекция переходов.** Полная траектория Q_m по всем шагам и репликам:
604800 × 2500 × 8 байт = 12.1 ГБ — не хранится. Вместо этого 35 наблюдаемых
извлекаются **внутри цикла интегрирования**:

- На каждом шаге: вычислить Q_m, сравнить с Q_thresh. При пересечении порога —
  записать момент перехода и тип (WAKE→SLEEP / SLEEP→WAKE) в буфер переходов.
- Текущий gain max/min за период бодрствования: обновлять running extrema.
  При переходе WAKE→SLEEP — сбросить running extrema, записать gain_swing дня.

Буфер на реплику: ~20 переходов × 2 float (время, тип) + 7 gain_swing + running
state (4 float). Итого: B × ~60 float = 2500 × 480 байт ≈ 1.2 МБ.

RAM итого: состояние (60 КБ) + параметры (60 КБ) + буфер наблюдаемых (1.2 МБ)
≈ **1.3 МБ**.

### Ожидаемые сложности

1. **v_vm и v_mv неразличимы.** Оба управляют силой взаимной ингибиции. Recovery
   покажет высокую кросс-корреляцию. Если подтвердится — один фиксируется.

2. **v_vc и alpha частично спутаны.** Амплитуда: длительность сна. Фаза: момент
   засыпания. Recovery должен разделить.

3. **Gain swing добавляет информацию.** Чувствителен к v_vh через H dynamics,
   помогает развязать v_vh и v_vc.

4. **sigma_vm, sigma_h, sigma_vv:** калибруются отдельно по вариабельности.
   Не входят в основной recovery.

### Порог (PROMPT_P2)

- **fitted** если r(θ, θ̂) ≥ 0.7 И |кросс-корреляция| < 0.6 с другими.
- **exploratory** иначе (выводится в песочницу с пометкой, правило 18).

## Критерий провала

- Нет бистабильности при baseline (нет flip-flop за 7 дней).
- Длительность сна вне [4, 14] ч при любых параметрах из диапазона.

## Наблюдаемые, которые модуль не воспроизводит

### Категория 1: не воспроизводимые

**(Пусто после D18.)** σ_h перекалиброван с 0.01 до 0.008 (D18).
Межночная вариабельность засыпания: median circ SD = 21.5 мин,
95% CI [20.6, 24.1] мин — в целевом диапазоне [15, 30] мин с запасом.

**Характеристика разброса (D18).** 50% реплик в [15, 30] мин,
22% ниже 15, 28% выше 30. IQR [15.8, 32.3] мин. При 7 ночах на
реплику оценка circ SD из ~6 наблюдений имеет высокую дисперсию,
отсюда ненулевые хвосты. Медиана устойчива (CI не пересекает границы).

**Правило для P4:** карта невозможного по межночной вариабельности
засыпания может строиться, но помечается зависимостью от σ_h.

### Категория 2: недостаточная разрешающая способность

**Onset advance (проверка согласованности #1).** Статус: INDETERMINATE.
CI [0.83, 1.77] ч перекрывает порог 1.0 ч (N=100, circ SD=2.41 ч).
Величина в принципе воспроизводима, но при доступных N и уровне шума
не измеряется надёжно.

Отличие от категории 1: при увеличении N или снижении шума статус
может измениться. Категория 1 — постоянное ограничение модели.

**Правило для P4:** карта невозможного по onset advance не строится.
При изменении N или шума — пересмотр статуса.
