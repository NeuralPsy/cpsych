# Спецификация среды (Environment)

Версия: 1.1. Дата: 2026-07-27. Статус: до реализации.

## Общее

Два протокола задач — две реализации единого контракта `Environment`:
1. **PerceptualTask** — перцептивная задача с градуированной трудностью (для DDM).
2. **ReversalBandit** — двурукий бандит с реверсиями и управляемой волатильностью (для RL).

Контракт: `next_trial(rng) -> stimulus`, `reward(action, rng) -> reward`, `reset(B, rng)`.
Составная среда (P3) получается композицией, не переписыванием. Если потребуется ломать
интерфейс — стоп и эскалация (D4).

## Протокол 1: PerceptualTask

### Первоисточник

Roitman JD, Shadlen MN (2002). Response of neurons in the lateral intraparietal
area during a combined visual discrimination reaction time task. *J Neurosci*
22(21):9475-9489. DOI: [10.1523/JNEUROSCI.22-21-09475.2002](https://doi.org/10.1523/JNEUROSCI.22-21-09475.2002)

Сырые данные (trial-level RT, coherence, correct/error, monkey ID):
https://shadlenlab.columbia.edu/resources/RoitmanDataCode.html

### Параметры

| Параметр | Значение | Источник |
|----------|----------|----------|
| Уровни когерентности | 0%, 3.2%, 6.4%, 12.8%, 25.6%, 51.2% | Roitman & Shadlen 2002, Methods |
| Число уровней | 6 | -- |
| Выбор уровня на пробу | равновероятно из 6 | -- |
| Направление движения | 2 (left/right), равновероятно | -- |
| Вознаграждение | +1 за правильный ответ, 0 за ошибку | упрощение vs juice reward |
| Число проб | не фиксировано; задаётся при вызове | -- |

### Контракт

```
next_trial(rng) -> {"coherence": (B,), "direction": (B,)}
reward(action, rng) -> {"correct": (B,), "r": (B,)}
```

- `coherence` in {0, 0.032, 0.064, 0.128, 0.256, 0.512}, выбор i.i.d. по пробам.
- `direction` in {-1, +1}, равновероятно.
- `action` in {-1, +1} — выбор модели.
- `correct` = (action == direction).astype(float).
- `r` = correct (для DDM стандартно: правильность = вознаграждение).

### Связь с DDM

Когерентность -> drift rate: v = kappa * coherence * direction, где kappa — sensitivity
(параметр модели DDM, не среды). Среда выдаёт только coherence и direction.

### Замечание: выбор данных

Данные Roitman & Shadlen — обезьяны, не люди. Это осознанный компромисс: monkey data
выбраны ради доступности сырых trial-level данных (RT, accuracy, coherence на каждой
пробе), которые необходимы для квантильного сравнения. Опубликованные человеческие
наборы для random dot motion обычно содержат только агрегированные сводки. Для
психиатрической песочницы, предназначенной для моделирования человеческих состояний,
это компромисс между строгостью валидации и релевантностью вида. Записан как D8 в
decisions.md.

### Стратегия разделения данных

Данные содержат двух обезьян (N и B). Стратегия:
- **Настройка**: monkey N (больший набор, ~1400 проб).
- **Отложенная проверка**: monkey B (~900 проб) — независимый субъект.

Это настоящая межсубъектная проверка, более строгая, чем внутрисубъектный held-out.
Оба набора квантилей вычисляются из roitman_rts.csv (правило 1). Результаты
докладываются по обоим субъектам раздельно.

Если данные monkey B окажутся недоступны или непригодны (слишком мало проб на уровень),
fallback: внутрисубъектный split monkey N (чётные/нечётные пробы). Записать в отчёте,
какой вариант использован.

## Протокол 2: ReversalBandit

### Первоисточник

Behrens TEJ, Woolrich MW, Walton ME, Rushworth MFS (2007). Learning the value
of information in an uncertain world. *Nat Neurosci* 10(9):1214-1221.
DOI: [10.1038/nn1954](https://doi.org/10.1038/nn1954)

### Параметры протокола (из Behrens 2007)

| Параметр | Стабильная фаза | Волатильная фаза | Источник |
|----------|-----------------|-------------------|----------|
| Число проб | 120 | 170 | Behrens 2007, Methods |
| P(reward\|correct arm) | 0.75 | 0.80 | Behrens 2007, Methods |
| P(reward\|wrong arm) | 0.25 | 0.20 | -- |
| Блок между реверсиями | inf (нет реверсий) | 30 или 40 проб (чередуются) | Behrens 2007, Methods |

### Параметризация среды

Реализация не копирует жёстко двухфазный протокол Behrens, а параметризует его
для управления из песочницы. Два осознанных отклонения от оригинала:

**Отклонение 1: развязка p_reward и volatility.** У Behrens p_reward связана с фазой
(0.75 в стабильной, 0.80 в волатильной). В нашей параметризации p_reward и volatility —
две ортогональные ручки. Это позволяет варьировать трудность (p_reward) и нестабильность
(volatility) независимо, что необходимо для parameter recovery и песочницы. Ценой
является невозможность точно воспроизвести оригинальный двухфазный протокол одним
набором параметров — для этого нужен двухблочный сценарий (реализуемый в P3 как
последовательность двух конфигураций).

**Отклонение 2: стохастические реверсии.** У Behrens реверсии через фиксированные 30/40
проб. Мы используем геометрическое распределение длин блоков, что делает момент реверсии
непредсказуемым для агента.

| Параметр среды | Тип | Диапазон | Default | Exposure |
|---------------|------|----------|---------|----------|
| p_reward | float | [0.5, 1.0] | 0.75 | internal |
| volatility | float | [0.0, 1.0] | 0.0 | **EXPOSED** |
| n_trials | int | [50, 1000] | 290 | internal |

Записано как D9 в decisions.md.

### Формула волатильности

Единственная формула:

```
if volatility == 0:
    no reversals (block length = infinity)
else:
    mean_block_length = 20 / volatility
```

Реверсия: длина каждого блока — выборка из Geom(1 / mean_block_length), т.е.
на каждой пробе P(reversal) = volatility / 20.

**Проверочные значения:**

| volatility | mean_block_length | Интерпретация |
|------------|-------------------|---------------|
| 0.0 | inf | стабильная фаза Behrens (нет реверсий) |
| 0.10 | 200 | очень редкие реверсии |
| 0.20 | 100 | редкие реверсии |
| 0.50 | 40 | умеренно волатильная |
| 0.57 | 35 | ~Behrens volatile (30-40 проб на блок) |
| 0.80 | 25 | высоко волатильная |
| 1.00 | 20 | максимально волатильная |

### Контракт

```
next_trial(rng) -> {"trial_index": (B,)}
reward(action, rng) -> {"r": (B,)}
```

- `next_trial` в standalone (P2) не несёт стимульной информации — бандит не предъявляет
  стимулов. Поле `trial_index` — монотонный счётчик проб, не плейсхолдер (правило 4).
  В P3 составная среда может добавить стимульные поля через композицию.
- `action` in {0, 1} — выбор руки.
- `r` = Bernoulli(p_reward) если action == correct_arm, иначе Bernoulli(1 - p_reward).

Внутреннее состояние (не часть x модуля):
- correct_arm: (B,) — текущая правильная рука.
- trials_in_block: (B,) — счётчик проб в текущем блоке.

### Тестирование бандита: эталонная политика

Агента на стадии P2-среды нет. Все тесты среды используют **фиксированную политику**:
`action = 0` для всех реплик на всех пробах. Это позволяет тестировать статистические
свойства среды изолированно от агента.

Следствия для тестов:
- Политика `action = 0` совпадает с correct_arm в ~50% времени (до первой реверсии —
  0% или 100%, затем чередуется).
- P(r | correct): policy выбрала правильную руку -> r ~ Bernoulli(p_reward).
- P(r | incorrect): policy выбрала неправильную руку -> r ~ Bernoulli(1 - p_reward).
- Тесты формулируются **условно на совпадение** action и correct_arm.

### Отложенный тест: поведенческая различимость по волатильности (P2.4)

Тривиальный parameter recovery волатильности из последовательности вознаграждений
(подсчёт точек смены) не информативен: он проверяет генератор, а не модель.

Правильный тест — **различимость поведенческой сигнатуры**: различаются ли
последовательности выборов обучающегося агента между уровнями volatility, с каким
размером эффекта и с какого числа проб. Этот тест требует модуль RL и выполняется
в P2.4 (RL + mood), а не при тестировании среды.

**Причина отложения:** тест волатильности — свойство системы «среда + агент», а не
среды в изоляции. Без агента проверяется только генератор.

## Тесты (статистические)

Все тесты — на B >= 100 репликах, seed фиксирован.

### PerceptualTask

| # | Тест | Критерий |
|---|------|----------|
| E1 | Распределение уровней трудности | max \|freq_i / expected − 1\| < 0.03 при n >= 600 (magnitude). Ранее: chi2 p > 0.01, заменён — при N=60000 chi2 ловит отклонения 0.3%, что ниже шума генератора (D17, принцип). |
| E2 | Баланс направлений | Binomial: \|n_left - n_right\| / n < 0.05 при n >= 200 |
| E3 | Отсутствие корреляций между соседними пробами | \|cor(coherence_t, coherence_{t+1})\| < 0.05 при n >= 500 |
| E4 | Вознаграждение при правильном ответе | accuracy = 1.0 при action == direction |
| E5 | Вознаграждение при ошибке | accuracy = 0.0 при action != direction |

### ReversalBandit

Политика тестов: `action = 0` (фиксированная). Условная статистика.

| # | Тест | Критерий |
|---|------|----------|
| E6 | Условная P(reward) vs p_reward | Отдельно для проб, где action == correct_arm: \|P_hat - p_reward\| < 0.03. Отдельно для action != correct_arm: \|P_hat - (1 - p_reward)\| < 0.03. При n >= 500 проб каждого типа. |
| E7 | Частота реверсий и средний блок | (a) Прямая частота реверсий: \|p_rev_observed - volatility/20\| < 0.003. (b) Средний блок ~ mean_block_length +/- 20%. KS/chi2 по блокам не используются: KS ненадёжен для дискретных распределений, chi2 переоснащён при >1000 блоков, усечённые хвосты конечных последовательностей вносят систематическое смещение вниз ~2%. |
| E8 | Внутриблочная независимость вознаграждений | Для проб внутри одного блока с одним и тем же соотношением action/correct_arm: runs test (число серий в бинарной последовательности r_t) — p > 0.01. Агрегируется по блокам длиной >= 10. |
| E9 | Волатильность 0 -> нет реверсий | При volatility=0, correct_arm не меняется за n проб (детерминированная гарантия, не статистическая). Проверяется на n=1000. |
| E10 | Волатильность 1.0 -> частые реверсии | Средний блок ~ 20 +/- 5 при n >= 200 |

## Наблюдаемые, которые среда не задаёт

Среда — генератор стимулов и вознаграждений, не модель поведения.
Наблюдаемые, характеризующие поведение (accuracy, RT, последовательности
выборов, learning rate), возникают из взаимодействия модуля со средой,
а не из среды в отдельности. Раздел формулируется как свойства
экспериментального протокола, не покрытые параметризацией.

1. **Поведенческая различимость по volatility (E11).** Отложен до P2.4.
   Тривиальное восстановление volatility из последовательности
   вознаграждений (подсчёт точек смены) проверяет генератор, не модель.
   Содержательная проверка — различимость поведения обучающегося агента —
   требует модуль RL.

2. **Адаптивная регулировка трудности.** PerceptualTask предъявляет
   когерентности i.i.d. из фиксированного набора. Адаптивная лестница
   (staircase) и зависимость стимула от предыдущих ответов не реализованы.
   В данных Roitman & Shadlen — тоже i.i.d., поэтому это не расхождение
   с данными, но ограничение для обобщения на другие протоколы.

3. **Структура реверсий.** ReversalBandit использует стохастические
   (Geom) реверсии вместо фиксированных 30/40 блоков Behrens. Это
   осознанное отклонение (D9). При необходимости воспроизвести
   двухфазный протокол Behrens — последовательность конфигураций (P3).

**Правило для P4:** карта невозможного строится по модулям, не по среде.
Среда задаёт протокол, в рамках которого измеряются модульные наблюдаемые.

## Отложенные наблюдаемые

Нет. Проверка среды — соответствие опубликованному протоколу (тесты выше).

## Оговорки

**PerceptualTask:** сырые trial-level данные доступны (Shadlen Lab). Квантили RT
вычисляются напрямую из roitman_rts.csv — это данные, а не опубликованные сводки.
Данные от обезьян, не людей (D8).

**ReversalBandit:** среда воспроизводит структуру протокола Behrens 2007, но
параметризована для управления из песочницы с двумя осознанными отклонениями (D9):
развязка p_reward/volatility и стохастические реверсии. Прямое сравнение с данными
Behrens невозможно (индивидуальные данные не опубликованы); проверка — на уровне
статистических свойств протокола (тесты E6-E10).

## Связь с P3

Составная среда `CompositeTask` в P3: перцептивный выбор (coherence -> DDM -> action)
с вознаграждением, контингенции которого реверсируются (бандит). Это именно композиция:
PerceptualTask выдаёт стимул, DDM принимает решение, ReversalBandit выдаёт reward
на основе DDM choice и текущего correct_arm. Если интерфейсы не компонуются — D4 стоп.
